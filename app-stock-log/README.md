# 盤後判斷簿

每日股票市場判斷紀錄與損益行事曆的前端，搭配 Google Apps Script + Google 試算表後端（`Code.gs` v2）。

純 HTML / CSS / JavaScript，沒有建置步驟，直接放上 GitHub Pages 就能用，也可以「加入主畫面」當 App 使用。

## 功能

- **行事曆**：每日損益熱度圖，點日期看當天每檔股票的判斷與損益
- **新增／編輯判斷**：日期＋股票代號為識別鍵；內建價差損益試算（含手續費與證交稅）
- **紀錄**：依日期區間、代號、方向、理由關鍵字篩選
- **股票**：股票主檔新增、編輯、刪除與搜尋
- **統計**：勝率、獲利因子、平均盈虧、累計損益走勢、依方向分組
- **離線**：沒網路時判斷會暫存在手機，恢復連線後自動以 `judgment.saveMany` 同步；讀取過的頁面離線也能看
- 漲跌色可切換台股（紅漲綠跌）／國際慣例；支援深色模式

## 部署步驟

### 1. 部署後端（Apps Script）

1. 開啟 Google 試算表 → 擴充功能 → Apps Script，貼上 `Code.gs`
2. 專案設定 → 時區改為 `Asia/Taipei`
3. 執行一次 `setupDatabase()` 並完成授權
4. 部署 → 新增部署作業 → 類型「網頁應用程式」
   - 執行身分：**我**
   - 存取權：**所有人**（前端是從瀏覽器直接呼叫，不能設為僅限登入者）
5. 複製結尾為 `/exec` 的網址

> 之後修改 `Code.gs` 時，要用「管理部署作業 → 編輯 → 新版本」更新，網址才會維持不變。

### 2. 部署前端（GitHub Pages）

1. 在 GitHub 建立一個 repository（例如 `stock-journal`）
2. 把這個資料夾內的所有檔案上傳到 repository 根目錄（包含 `.nojekyll`）
3. Settings → Pages → Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾 `/ (root)`
4. 約一分鐘後開啟 `https://你的帳號.github.io/stock-journal/`

### 3. 連接

開啟網站 → 右上角齒輪 → 貼上 `/exec` 網址 → 測試連線。

若不想每台裝置都手動輸入，可以把網址寫進 `config.js` 的 `apiUrl`。

## 安全性：請務必讀

- `config.js` 和整個 repository 都是**公開的**，**不要**把 API Token 寫進任何檔案。Token 只在「設定」頁輸入，存在該裝置的瀏覽器裡。
- 後端 `API_TOKEN` 留空時，**任何知道 `/exec` 網址的人都能新增、修改、刪除資料**。正式使用前，建議在 Apps Script 的「專案設定 → 指令碼屬性」新增 `API_TOKEN`，並在每台裝置的設定頁輸入同一組 Token。
- Token 只是共用密碼，不是完整的帳號系統；若網址與 Token 外流，請更換 Token。

## 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 頁面骨架與底部導覽 |
| `styles.css` | 樣式（淺色／深色、漲跌色） |
| `app.js` | 全部邏輯：API、路由、各頁面、離線佇列 |
| `config.js` | 可選的預設 API 網址 |
| `sw.js` | Service Worker，快取前端檔案供離線開啟 |

| `.nojekyll` | 讓 GitHub Pages 直接提供檔案、不經 Jekyll 處理 |

## 常見問題

**測試連線出現「回應不是 JSON」**
部署的存取權不是「所有人」，或貼成了 `/dev` 網址。請改用 `/exec` 並確認存取權。

**出現「授權失敗」**
後端已設定 `API_TOKEN`，設定頁的 Token 不一致。

**更新了前端，手機上還是舊版**
Service Worker 採網路優先，重新整理一次即可；若仍是舊版，關閉 App 後重開。

**在試算表直接改了資料，行事曆沒更新**
後端讀取快取最多 2 分鐘；可到設定頁按「重建行事曆」。

**損益試算的費用怎麼算**
手續費 0.1425%（每筆最低 20 元）、證交稅 0.3%（賣出時），未計券商折扣與當沖減半，僅供參考。存進去的是表單上「損益」欄位的數字。
